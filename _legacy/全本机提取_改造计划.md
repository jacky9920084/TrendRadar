# 全本机提取（抖音 + 网页）改造计划（先写死，不做二选一）

## 0. 一句话结论
把“下载视频/抓网页/调用 Gemini/重试/日志”全部放到本机（TrendRadar）做；Cloudflare 只保留“拉清单 + Step3/Step4 拼接材料 + 写结果”的轻后端。

---

## 1. 最终目标（跑完一天后你应该看到什么）

### 1.1 R2 必须有两类材料（都写在 ai-materials）

**A) 抖音材料（视频增强）**
- Key：`ai-materials/YYYY/MM/DD/douyin/{videoId}.json`
- 产出字段（必须稳定）：
  - `text`：视频文案/口播/字幕（提取后文本，长度受控）
  - `visual`：画面要点（长度受控）
  - `why_hot`：一句话“为什么会火”（轻量归因）
  - `meta`：抓取与排障信息（见第 3.3）

**B) 网页材料（正文增强）**
- Key：`ai-materials/YYYY/MM/DD/web/{sha1}.json`
- 产出字段（沿用现有方案）：
  - `excerpt`：摘要
  - `clean_text`：正文纯文本（长度受控）
  - `meta.blocked_reason / meta.error`：失败占位

### 1.2 Hotspot-Spark Step3/Step4 必须能“自动吃到”材料
- 输入仍然是旧源主清单：`ai-hotspots/YYYY/MM/DD/hotspots.txt`
- Step3/Step4 拼接规则：
  - 有抖音材料就追加 `[AI_TEXT] / [AI_VISUAL] / [AI_WHY_HOT]`
  - 有网页材料就追加 `[AI_EXCERPT] / [AI_WEB_TEXT]`
  - 没材料就只用标题+链接兜底（不影响跑通）

## 2. 组件分工（写死，不再讨论）

### 2.1 TrendRadar（本机）= 重活中心
负责：
- 拉抖音清单（从 Hotspot-Spark 的接口）
- 解析可下载 MP4（本机 video_spider）
- 下载 MP4（仅本机临时文件，最后要自动删除）
- 调 Gemini Flash 提取 `text/visual/why_hot`
- 写入 R2（只写 json 文本材料，不写 mp4）
- 抓取网页正文并写入 R2（你已落地 web 链路，保持）
- 全链路日志（每天一份 log，便于排障）

不负责：
- 选题 Step3/Step4

### 2.2 Hotspot-Spark（Cloudflare）= 轻后端
负责：
- 从 TopHub 拉热榜清单并缓存：`GET /api/hotlist/douyin`
- Step3/Step4（读取主清单 + 读取材料 + 调 Gemini 选题）
- 覆盖率统计接口（只读 R2）：`GET /api/douyin/materials`、`GET /api/web/materials`

不负责：
- 下载 MP4
- 调 Gemini 做“视频提取”
- 任何长耗时后台任务（避免 pending/processing 卡死）

### 2.3 video_spider（本机）= 只负责解析 URL
负责：
- 输入抖音分享文本或长链 → 输出 `mp4_url`

## 3. TrendRadar：需要新增的“抖音本机提取”链路（核心任务）

### 3.1 新增入口脚本（PowerShell）
新增文件（建议命名，不要起 v1/v2）：
- `E:\cursor\TrendRadar\run-daily-newsource-douyin-local.ps1`

功能：
1) 读取日期（默认上海当天；支持补跑）
2) 拉抖音清单：
   - `GET https://hot-sparks.jacky.onl/api/hotlist/douyin?date=YYYY-MM-DD&refresh=1`
3) 对每条视频：
   - 交给 `video_spider` 拿 `mp4_url`
   - 本机下载 mp4 到临时目录（跑完删除）
   - 调 Gemini Flash 提取 `text/visual/why_hot`（严格 JSON）
   - 写入 R2：`ai-materials/YYYY/MM/DD/douyin/{videoId}.json`
4) 记录日志：
   - `E:\cursor\TrendRadar\output\newsource-douyin-local-YYYY-MM-DD.log`

并发建议：
- 默认 2（最多 3），避免把带宽/Gemini/下载打爆

### 3.2 新增实现脚本（Python）
新增文件：
- `E:\cursor\TrendRadar\newsource_douyin_local.py`

要求：
- 只依赖稳定库（建议沿用已存在的 `requests` / `boto3`）
- 对每条视频“失败也要写占位材料”，避免下游统计与排障断档
- 严格控制输出文本长度（防止 Step3 prompt 膨胀）

### 3.3 抖音材料 schema（写死）
写入 `ai-materials/YYYY/MM/DD/douyin/{videoId}.json` 的 JSON 格式固定为：

- 顶层字段：
  - `schema_version`: number（固定 1）
  - `platform`: string（固定 `"douyin"`）
  - `item_id`: string（固定 `{videoId}`）
  - `source_url`: string（视频页 URL）
  - `title`: string
  - `kind`: string（固定 `"video"`）
  - `text`: string（允许空字符串）
  - `visual`: string（允许空字符串）
  - `why_hot`: string（允许空字符串）
  - `meta`: object

- `meta` 字段（最少要这些）：
  - `fetched_at`: ISO 字符串
  - `normalized_source_id`: string（`videoId`）
  - `mp4_url`: string（用于复现；不存 mp4 文件）
  - `blocked_reason`: string（成功则空字符串）
  - `error`: string（失败原因简述）
  - `attempts`: number（本机重试次数统计）
  - `gemini`: object
    - `model`: string（例如 `gemini-3-flash-preview`）
    - `usage`: object（可选，能拿到就存）

长度约束（硬约束）：
- `text`：最多 4000 字符，超出截断并加 `...(truncated)`
- `visual`：最多 1500 字符
- `why_hot`：最多 300 字符

### 3.4 Gemini 提取提示词（必须用现成的，不准缩水）
提示词来源（必须整段原样使用，不准删减/压缩/改写）：
- `E:\cursor\Hotspot-Spark\gemini提示词（提取画面+文案）.md`

执行要求（写死）：
- **提示词必须整段原样使用**（不要“精简版/缩水版”），否则提取质量会明显下降。
- 不要把完整提示词打印到日志/控制台（避免日志膨胀与泄露）。

### 3.5 Gemini 调用参数（写死）
视频提取调用（本机）固定参数：
- 模型：Gemini Flash（与 Hotspot-Spark 当前一致，建议继续用 `gemini-3-flash-preview`）
- `temperature = 0.8`
- `maxOutputTokens = 30000`
